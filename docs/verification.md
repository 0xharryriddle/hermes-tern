## Evidence classes

| Class | Establishes | Does not establish |
| --- | --- | --- |
| Source inspection | A named revision defines a contract | Installed runtime behavior or stability |
| Unit/CLI behavior | Code handles controlled inputs and errors | Native rendering or provider integration |
| Structural docs checks | Local links/fragments/navigation and task graph are consistent | Semantic fidelity or current external facts |
| Scripted transport fixture | Parser/state behavior for supplied frames | Those frames occurred on the wire |
| Real Tern offscreen render | Actual preview/labelled fixture text and native geometry/image generation | Window plugin executed, input/action behavior, visual quality or Hermes connection |
| Real plugin-window check | Actual Luau action loaded and launched intended command | Live agent capability |
| Live runtime check | Exact supported session/approval/cancel path works | Every configuration, scale or failure mode |
| Load/fault campaign | Measured envelope for pinned host/workload | Unlimited scale or guarantees outside that envelope |



The wrapper additionally checks whitespace in tracked and untracked source and runs `git diff --check`. Failures propagate; no final success line may follow a failed command. CI uses the same wrapper, but is not asserted to have run remotely.

Rust CLI tests exercise the compiled binary, not a fake SDK. They cover help/default behavior, version, forced-plain preview, extra arguments, unknown commands and a forbidden unimplemented `run` command. The initial empty program was observed failing all these behavior assertions before implementation.

A false-pass checker was observed failing the negative controls before implementation. Package tests check manifest/entry structure, not Luau execution.

The docs checker supports inline Markdown links outside fenced code; external URLs are not fetched by CI. Reference links/HTML anchors are not part of its supported syntax. Keep docs within that subset or extend the parser with positive and negative tests. Evidence strings in tasks are structural references; reviewers must verify the cited behavior, not merely their presence.

## Proposed runtime campaign

Start with two Hermes peer actors and one opt-in OMP actor in isolated workspaces. Use a deterministic local test runtime first to prove transport/error paths, then a separately approved provider-backed run to prove real semantics. Keep these denominators separate. Record runtime revisions, provider/model, host characteristics, concurrency, event sizes, sample count, timeout policy and exact failures.

For scaling, compare one, two and four active actors using identical workload definitions. Record submission-to-acceptance, acceptance-to-consumption where measurable, event-render delay, memory high-water mark, queue bytes, journal bytes and cancellation observation latency. Choose product performance targets after the baseline; do not invent passing latency thresholds from unmeasured expectations.

## Evidence discipline

Every task closure names the command, environment scope, result and limitations. Record collected/executed/passed/failed/skipped separately when supported. A skipped provider test is not passed. Tern surface ACKs are not task acknowledgements. Process exit code is not model task correctness. A source pin is not a security audit. A conditional reviewer GO for the bootstrap plan is not approval of the finished runtime architecture.
