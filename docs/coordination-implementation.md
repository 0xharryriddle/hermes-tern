# Durable coordination implementation tranche

Status: local store/IPC, physical-session Rust bridge and six Hermes tools implemented. Process fixtures and the real pinned Hermes loader/registry pass in an isolated home; provider-backed live-agent integration and canonical continuity remain open. This refines [protocol](protocol.md), not an alternate authority. [tasks.json](tasks.json) remains the task-state ledger.

## Boundaries

- Separate `crates/store`, `crates/supervisor` and `crates/cli` libraries, composed by `bin/hermes-tern`. No provider loop or Hermes database access. See [workspace layout](workspace-layout.md).
- One private state directory per canonical workspace, supervisor lock and Unix socket; persisted actor UUID/incarnation and hashed credentials. Peer credentials grant mailbox operations only. Operator credentials grant registration/routes/lifecycle, never conveyed in peer text.
- The optional Hermes plugin obtains session identity from verified runtime context; no model-supplied sender identity. A missing supported identity means unavailable, not fallback to user-prompt injection.
- Mailbox delivery is pull-based, attributed tool-result data. Reading transitions queued to submitted; explicit actor acknowledgment reaches consumed. Crash after selection/read before acknowledgment recovers to ambiguous; re-offer requires explicit operator disposition, not automatic duplicate delivery.
- Peer task leases fence completion. Expired ownership cannot be reassigned automatically; operator must attest the prior writer stopped before reassignment. Workspaces and leases are not a sandbox.
- Native OMP is a human-confirmed handoff, not autonomous peer delivery. No approval or role-escalation messages exist in the mailbox vocabulary.

5. Native OMP bridge only after the exact Luau callback and AgentCx contracts are verified. Direct RPC probe keeps separate credentials/runtime and chooses a restrictive approval mode explicitly.

### Implemented local slice: revision-bound complete operator state pages

Operator-only `state-index` and `state-page --workspace UUID --epoch UUID --revision HEX --section NAME --offset N --limit N` supplement the existing 128-row overview and invalidation notices; they do not reinterpret incomplete events as a reconstructable log. They enumerate actors, routes, messages, tasks, dispositions, migrations and retained events in deterministic unique-key order. Payloads/results and explicit operator-reoffer provenance remain attributed untrusted data; no credential values or token hashes are returned. Index contains exact counts, schema/clock/sequence watermarks and an opaque revision, not a restoration capability.

Each request opens a read transaction, validates bounded persisted state and derives the same domain-separated SHA-256 revision from typed logical rows of every coordination table, metadata and allocation counters. No long-lived snapshot, new persistent table or hidden queue is introduced. Pages require matching workspace, store-open epoch and revision inside that transaction; stale epoch/state returns `restart_required`, empty items and no continuation. The consumer discards its partial assembly and fetches a new index. Semantically identical rows can share a revision; this is coherence detection, not authenticated anti-rollback or hostile same-user exclusion. Source writes and clock-only updates may invalidate a walk; quiescent export or bounded retries are operational requirements.

Offsets are canonical nonnegative decimal strings bounded by the selected collection count; page limits are 1–128. Emit complete records up to the count and encoded response budget (393216 bytes), expose `next_offset`, exact total, `has_more` and byte-limit truncation, and never claim completion when rows remain. Reads neither deliver/ACK/expire messages nor mutate task/clock/event state. Index/page contents are persisted state, not runtime liveness, execution correctness, an archive, a backup or authority to restore. Keep the existing event API and peer schemas unchanged.
