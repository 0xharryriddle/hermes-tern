## Local protocol and storage

`hermes-tern omp-handoff exchange --state ABSOLUTE_PRIVATE_DIR` reads one UTF-8 JSON document, at most64KiB, with a two-second EOF deadline, and returns one bounded JSON response on stdout. Logs/errors are static stderr. No inference, environment-derived state default, process launch or dispatch occurs in Rust. The local same-user operator controls the state path; this is not a new credential or peer-authorization channel.

Closed envelope: `v:1`, canonical UUID `request_id`, `op` tagged by `type`. Operations:

The offer request ID is its idempotency key. Subsequent bridge exchanges use the handoff ID as their envelope request ID and match the operation name; this is correlation, not authentication. Replies contain `v`, `request_id`, `op`, and the immutable `proposal` (`v`, offer `request_id`, `handoff_id`, `attempt_id`, `target_id`, `digest`, `text`, `source`). Prepare/inspect add `armed`, `observations` and `outcome` (`not_armed` or `unknown`); arm adds `newly_armed`; record echoes `event`. Any arm remains `unknown`, including no observations or an idle observation, because none is a durable consumption receipt. The target UUID is an opaque attempt-correlation slot, not an actor or persisted pane binding. The exact selected pane/Agent handle exists only inside the window VM.

- `offer {text,source}`: source is a nonblank untrusted single-line label of at most 256 UTF-8 bytes; controls, Unicode line/paragraph separators and bidi controls refuse. Text is 1..8192 bytes, no controls except newline/tab, no leading `/`, `!`, `$`, `@` after whitespace, and no bidi/terminal controls. Persist immutable proposal and Rust-generated handoff UUID. Exact same request/body retry returns the original; changed body refuses. Prefix rejection is defense in depth, not a guarantee that OMP extensions never interpret an ordinary-looking prompt as a command.
- `prepare {handoff_id}`: read immutable proposal/digest plus Rust-generated attempt/target UUIDs fixed at offer. No mutation/authority. Payload, source and identifiers must match on the bridge response.
- `arm {handoff_id,attempt_id,target_id,digest}`: exclusive commit before ask. Only first durable arm returns `newly_armed:true`; every repeat returns false, including lost-response/restart. A grant is only a dispatch fence, never proof that a human approved. Human confirmation exists solely in the local Luau UI path.
- `record {handoff_id,attempt_id,target_id,event}`: append one of `ask_returned`, `idle_observed`, `outcome_unknown` as observations. Exact repeated observation is idempotent; no observation creates a consumed/completed receipt or new send grant. Unknown remains explicit even if another observation exists.
- `inspect {handoff_id}`: read proposal and retained observation flags. No resend, ACK, task completion, deletion or authority restoration.

Use a separate state directory and independent short-lived exclusive flock, not the coordination database/owner lock. Bound 64 admitted proposals and a fixed number of files per proposal. Owner-only non-symlink regular files, fixed names, strict JSON/UUID/digest, no hardlinks; reject malformed/partial/unknown retained data. The state parent must already exist at its canonical path. Offer creation/retry syncs the lock, state directory and its parent before publishing a proposal; no intermediate directories are created. Immutable create-new files, file fsync then containing-directory fsync precede positive publication replies. A crash/failed sync leaves retained uncertainty; never remove an arm marker to retry. An orphan/partial file fails closed, not a successful replay. Validate the bounded inventory before processing. Normal file operations cannot exclude a malicious same-user writer; no such claim.

## Window bridge

Register an explicit handoff palette command; loading performs no I/O or process launch. Read only explicitly configured `HERMES_TERN_HANDOFF_BIN` (absolute executable path) and `HERMES_TERN_HANDOFF_STATE` when invoked. A prompt asks for the exact handoff UUID. Use fixed argv, request JSON on stdin and bounded process timeout; never interpolate text in a shell command. Correlate envelope/UUIDs/digest and require status0,not timed_out,bounded output before advancing.

Choose an existing local connected idle agent pane with an `omp.session` inline snapshot, exactly one plain `omp.editor` subtree/editor in `dock`, empty text, sendable=true, no shell/focused-subagent roles and no capped/unknown nodes. Require the empty `layer` region root, not its absence: pinned OMP `native/reconcile.ts:265–270` always adds main/dock/layer; its `detachLive:312–334` describes dropping dock/layer on retained close. Main-only retained content and editors outside dock refuse. The producer's inline session and fullscreen overlay distinction is source-verified at `native/backend.ts:6–11,341,527–550`; switching to screen-only would reject the ordinary composer.

These are snapshot suitability checks, not an atomic liveness/session proof. The pinned window API explicitly allows retained surface reads and `ask` takes only agent/text; it cannot condition delivery on the inspected surface/editor incarnation. The UI warns about that limitation and asks for one pane-level call that may queue. Preserve exact pane IDs and Agent handles in the VM, recheck before consent and immediately before ask, and refuse observed drift. Do not claim unchanged snapshots prevent every concurrent change, authenticate a durable OMP actor, or lock the composer at eventual delivery. Strict conditional-send users must not use this lane; that capability requires an upstream API or separately qualified adapter.

Open/reuse one owner-tagged inert code/text review canvas with exact proposal/source and target warning, then require explicit Send-once versus Cancel selection. The canvas persists in Tern session state and retains the last reviewed prompt; do not include secrets. Multiple matching review canvases refuse rather than choosing arbitrarily. Every asynchronous continuation uses the supplied fresh WindowCx. One in-flight flow per VM, a two-minute deadline, cancelled completion timer and single-use callbacks prevent reentry/stale callbacks. The arm reply must be freshly granted before one `cx.agents:ask` call. Record ask-returned as queued/submitted; wait idle records only an observation. Any error/lost callback leaves unknown; an armed record without observations is also unresolved. Never start/stop/interrupt agents, answer approvals, type terminal input, auto-ACK a mailbox or claim task completion. Readback text is deferred in v1 to avoid uncorrelated output/export; the operator can inspect OMP directly.
